We ingest third-party Git bundles before publication. Repair the Go code under `/app/environment` (packages p7, k2, q4, lib/m3) and build `/app/admit-repo` using `/app/environment/docs/outcome_rules.md` as the contract. Write `/app/output/object_trust_report.json` with fields schema_version, repo_path, release_ref, walk_records, and walk_digest defined in outcome rules. Hand-written JSON is insufficient; the report must be generated by the `/app/admit-repo` CLI binary, which must be built via `make -C /app/environment build` before use. Any principal whose id and fingerprint appear in `/app/policy/signer_matrix.toml` is admissible regardless of its format lane; FMT_LANE is only raised when a signature's observed principal is absent from signer_matrix.toml entirely.

The CLI exits 0 when the repo is admitted and 2 when it is rejected; exit code 1 signals a usage error. Every rejection writes a `rejection` object to the report with a `code` field drawn from these values: RPL_MAP (replace-ref mapping present but walk closure incomplete), SHLW_GAP (shallow boundary leaves ancestry incomplete), TAG_ANCHOR (annotated tag or commit anchor does not cover required closure), FMT_LANE (signature format lane does not match signer matrix — principal absent from signer_matrix.toml).

That document covers `/app/policy/signer_matrix.toml`, `/app/policy/release_rules.toml`, `/app/environment/fixtures/policy/ref_matrix.toml`, and `/app/environment/fixtures/gen/replay_mutator.py`. Tests run via `/tests/test.sh`.
