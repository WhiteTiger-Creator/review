The Hanabi firework table at `/app/bin/hanabi` is built from the Go module under `/app`. Verification rebuilds `/app/bin/hanabi` from `/app/cmd/hanabi`, clears `/app/output/`, then runs that binary — so championship behavior must be present in the rebuilt binary (not in a separate replacement that only writes output beforehand). Run `/app/bin/hanabi` so each scenario under `/app/scenarios/` (order from `/app/config/engine.json` `scenario_order`) produces `/app/output/<scenario>/session_log.json`, and also write `/app/output/summary.json`. The engine must enforce cooperative championship play documented in `/app/docs/firework-ruleset.md`. Where `/app/docs/club-night.md`, profiles under `/app/config/profiles/`, comments, or docstrings disagree, the firework ruleset controls. Leave `/app/scenarios/`, `/app/config/engine.json`, and `/app/config/profiles/` unchanged.

Each `/app/output/<scenario>/session_log.json` must be JSON with keys `scenario` (string), `moves_applied` (JSON array of ints, never JSON null — use `[]` when empty), `moves_rejected` (JSON array of ints, never JSON null — use `[]` when empty), `final_info_tokens` (int), `final_fuse_tokens` (int), `fireworks` (object with int keys `R`,`Y`,`G`,`B`,`W`), `score` (int, sum of firework heights), `game_over` (bool), `end_reason` (string: `"none"`, `"fuse_out"`, `"perfect"`, or `"deck_end"`), `hints_given` (int), `cards_played` (int), `cards_discarded` (int), `ply_count` (int, equal to len(`moves_applied`)), and `final_player` (int). Ownership and ending semantics for `final_player` and `end_reason` must match the firework ruleset. `/app/output/summary.json` must be JSON with keys `scenario_count` (int), `total_score` (int), `total_hints` (int), `total_plays` (int), `total_discards` (int), `total_plies` (int), and `end_reasons` (object counting `none`, `fuse_out`, `perfect`, `deck_end`). Note that code comments and docstrings may themselves contain errors.
