We replace an nftables input chain remotely and need an operation order that never locks out management or briefly exposes a forbidden flow. Build `/app/bin/lockout-guard`, a Go CLI accepting `--current`, `--desired`, `--probes`, and `--output`; their defaults are `/app/task_file/current.json`, `/app/task_file/desired.json`, `/app/task_file/probes.json`, and /app/out/plan.json. Both ruleset files contain `{"policy":"accept|drop","rules":[...]}`. Each rule has a unique `id`, integer `position`, IPv4 CIDR `source`, integer `port` where 0 means any, and `accept` or `drop` `verdict`. Rule array order is irrelevant: traverse by position then ID as UTF-8 bytes, take the first rule whose CIDR contains the packet source and whose port is 0 or exactly matches, and otherwise use policy. `probes.json` contains objects with `source`, `port`, and `must`.

Derive the operations rather than reading them: delete every current ID absent from desired, add every desired ID absent from current, replace every shared ID for which any field differs, and change a differing policy with one policy operation. Delete removes the ID, add inserts its desired rule, replace atomically substitutes its desired rule (including its new position), and policy changes only the fallback. Operation JSON is `{"op":"add|delete|replace","id":ID}` or `{"op":"policy","verdict":VERDICT}`. The initial state and every state after one complete operation must satisfy every probe, and the final policy and rules must exactly equal desired; if the initial state is unsafe or no complete safe order exists, return no operations. The already-converged boundary case likewise has zero operations.

Write exactly `{"operations":[...]}` and use every derived operation exactly once in a successful plan. Among safe orders, first minimize the peak rule count across the initial and all post-operation states, then choose the bytewise lexicographically smallest complete sequence of `op+":"+id` keys, using the verdict in place of the policy operation's ID. This is a whole-plan tie-break, not a next-step heuristic. The verifier reruns the program with schema-preserving mutations containing up to 64 current rules, 64 desired rules, 256 probes, and 20 derived operations, so the 20-operation bound must work without enumerating all permutations.
