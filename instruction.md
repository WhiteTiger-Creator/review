Consider a triangulated surface mesh whose vertices carry integer coordinates and whose faces are triangles. For an integer direction vector the height of a vertex is the dot product of its coordinates with the direction. A vertex enters the height filtration at its own height, and an edge or triangle enters at the greatest height attained by its vertices. For a real threshold t the Euler characteristic of the sublevel complex is the number of vertices whose height is at most t, minus the number of edges whose entry height is at most t, plus the number of triangles whose entry height is at most t. As t runs over the reals this Euler characteristic is a step function of t: it is zero below the smallest height, constant between consecutive heights, and right continuous, so its value at a height already accounts for every simplex entering there. The breakpoints of that step function are the heights at which its value differs from the value it holds immediately below, and each breakpoint is reported together with the value the curve takes from that height onward. The ordered collection of these step functions over the family of directions supplied with an instance is the directional Euler-characteristic-transform census of the mesh. The undirected edges of a mesh are the distinct unordered vertex pairs that occur in any triangle. Direction components may be large and of either sign, and are not all zero, so the heights of a single mesh can span more integers than could ever be enumerated one at a time. The census is defined over the exact integers, and every height, threshold comparison and breakpoint is exact.

The same undirected edges define the one-skeleton graph of the mesh: its vertices are the mesh vertices and its edges are those distinct unordered pairs, each taken once, so the graph is simple and carries no multiplicities. Let n be the number of vertices. The Laplacian of this graph is the n by n integer matrix whose diagonal entry for a vertex is its degree and whose off-diagonal entry for a pair of vertices is minus one when they are adjacent and zero otherwise. Deleting the last row and the last column leaves the reduced Laplacian, an n minus one by n minus one integer matrix. The critical group of the mesh, also called its sandpile group, is the cokernel of the reduced Laplacian over the integers: the quotient of the integer lattice of rank n minus one by the image of that matrix. It is a finite abelian group, and the task asks for its structure exactly. Written as a direct sum of cyclic groups with each order dividing the next, its invariant factors are the integers d_1 dividing d_2 dividing up to d_m, every one of them greater than one; these are the torsion coefficients of the group and they are what must be reported, in increasing order. The number of spanning trees of the graph, written tau, equals the order of the critical group, which is the product of all the invariant factors and also equals the absolute value of the determinant of the reduced Laplacian by the Matrix-Tree theorem. The meshes are connected, so the critical group is a nontrivial finite group whenever the graph has a cycle, and tau is at least one.

These quantities are exact integers and they are large. On the graded instances tau and the largest invariant factors exceed the range of every fixed-width machine integer and run to hundreds of bits, so every intermediate value in their computation must be held in exact arbitrary precision; a computation that loses precision or wraps a fixed width will not reproduce them. The structure itself is what is required, not a proxy for it: the rank of the Laplacian over a field, or over the rationals, counts only connected components and is blind to every torsion coefficient, so it is not an answer; a determinant taken in floating point cannot represent tau once it grows past the exact range of the format and is not an answer either. A naive exact reduction that lets the entries grow without bound will not finish within the time available on the larger instances, so tau and the invariant factors must be reached by an exact method that keeps its intermediate quantities bounded.

Each instance also supplies, for every direction, a list of query thresholds. The feature vector of a mesh is the concatenation, in direction order and then in threshold order within a direction, of the Euler characteristic of the sublevel complex at each of those thresholds. Every label carries the same number of reference meshes; call that number k. For each label let S be the elementwise sum of the feature vectors of the reference meshes with that label. The predicted label of a query mesh with feature vector q is the label that minimises the sum over all components of the square of k times q minus S. If two labels tie on that value, choose the smaller label identifier.

A program reads one instance and writes the census to standard output. The program is invoked with one command line argument, the path of an instance directory, and it prints the required lines to standard output and nothing else. The graded program is the release binary compiled with cargo from the sources under src, and the worked example under example together with its expected output confirms the parsing and the output format; the graded instances are different and are not present in the environment. An instance directory contains these files. params.csv has a header field,value and one row G,<integer> giving the coordinate grid size. directions.csv has a header dir_id,nx,ny,nz and one row per direction, with identifiers numbered from zero. thresholds.csv has a header dir_id,slot,t and one row per query threshold, where slot numbers the thresholds of a direction from zero and t is the threshold. meshes.csv has a header mesh_id,role,label; role is either reference or query; label is an integer for a reference mesh and -1 for a query mesh. For every mesh listed there is a file vertices/<mesh_id>.csv with header vid,x,y,z and a file faces/<mesh_id>.csv with header v0,v1,v2. Vertex coordinates are integers from 0 to G inclusive, and each face lists three zero-based vertex identifiers of a triangle.

The output has five parts, printed in this order and separated by single spaces, with nothing else. First, for every mesh in ascending mesh_id order and every direction in ascending dir_id order, print one line of the form ECT followed by a space, the mesh_id, a space, the dir_id, a space, the number of breakpoints of that curve, and then, in ascending order of height, that height and the value of the curve from it onward. Second, in the same mesh and direction order, print one line of the form VAL followed by a space, the mesh_id, a space, the dir_id, and then the Euler characteristic at each query threshold of that direction in ascending slot order. Third, for every mesh in ascending mesh_id order, print one line of the form CG followed by a space, the mesh_id, a space, the number m of invariant factors greater than one, and then those invariant factors in increasing order, so that each divides the next; when the critical group is trivial m is zero and no factors follow. Fourth, in the same mesh order, print one line of the form TAU followed by a space, the mesh_id, a space, and the number of spanning trees. Fifth, for every query mesh in ascending mesh_id order, print one line of the form LABEL followed by a space, the mesh_id, a space, and the predicted label. Print nothing else. Meshes have up to a few hundred vertices and a few thousand triangles, and each instance supplies at most a few dozen directions. All computation is deterministic and offline.
