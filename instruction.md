The scoreboard tool in `/app` is `handsettle`, a Go program built with `make` (it produces the executable `/app/handsettle`) that our riichi club uses to settle a night's play from its hand log. The package `/app/internal/settle` is unimplemented, so the program cannot report anything yet.

Implement it so that `./handsettle <hand-log.json>` prints a JSON array on stdout with one report object per logged hand, in log order. Each report gives the hand's han and fu, the yaku it holds, and the payment split; a hand that turns out to hold no yaku is reported as unscored instead. The tile notation, the report format with worked payment examples, the exact yaku names to use, and the house rules our table plays under are all written up in `/app/docs/scoring-rules.md`. Every report has to agree with the settlement our club engine produces for the same hand. A hand that can be read as more than one arrangement of sets settles the way that engine settles it, and quads, called sets, wait shapes, seat and round winds, dora indicators, red fives, bonus counters and riichi sticks all have to come out right.

Eighty-two worked hands with the settlement the club engine recorded for them are in `/app/examples`; `make test` replays them. Keep the `make` build working and keep the reported field names.
