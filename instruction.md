# SSO gateway token-exposure reconstruction

During last week's SSO gateway incident, analysts replayed NDJSON event shards from `/app/data/events` and got bearer-hop leakage, scope escalation, signing-key reuse, revocation lag, and refresh-replay signals that did not line up across the OPA policy bundle in `/app/opalib` and the Go publication code that drives `/app/bin/token-exposure-analyze`. Notes in `/app/data/incident/` are background only; every finding must come from rerunning the analyzer over the corpus.

Repair the Rego library and Go harness so the analyzer rebuilds exposure chains and publishes a coherent report. Use the contracts under `/app/docs/` for token lineage, forwarding, scope decisions, findings, event-shape tolerance, generated cases, recovery, publication, graph rendering, and token redaction. Chain correlation is tenant-scoped and follows the documented exchange → trace → refresh-family → request priority. Trust-boundary forwarding must honor `/app/config/trust-boundaries.json`. Optional and nested payload shapes must be tolerated without evaluation errors, and blocked or attempted forwards belong in `rejected_candidates` rather than exposure findings.

Run `/app/bin/token-exposure-analyze` with `--events`, `--config`, `--regolib`, `--state`, and `--output`. Write `/output/token_exposure_report.json` and `/output/token_exposure_graph.dot`. The JSON must validate against `/app/schemas/exposure-report.schema.json`, use `schema_version` 2, and include `evidence_fingerprint`, `analysis_revision`, `findings`, `rejected_candidates`, `nodes`, and `edges`. The DOT must start with `digraph`, parse in Graphviz, and mirror the JSON graph per `/app/docs/graph-contract.md`, including the documented chain and finding node kinds. JSON and DOT must agree on nodes, edges, and exposure paths. Token fingerprints may be used internally for correlation but must be redacted in published output according to `/app/docs/redaction-contract.md`.

Publication must follow `/app/docs/publication-contract.md` and `/app/docs/recovery-contract.md`: equivalent shard layouts produce identical bytes, checkpoint/resume does not drop or duplicate evidence, only relevant fingerprint changes force invalidation, and partial snapshots must not be published. Preserve the legacy compatibility fields documented for the analyzer. The workflow is offline-only. Copied or hand-written `/output` artifacts will not satisfy the verifier, which reruns the analyzer and checks regenerated output. Do not modify integrity-checked inputs listed in `/app/docs/trusted-fixtures.json`.
