This host moves tenant egress traffic through a fleet of shaped network interfaces, and every one of them needs its shaping policy provisioned from the link ledger registry. An active interface gets a unix group plus a nologin user with a fixed uid. It also gets a state directory under /var/lib/link-rate that the user owns, a systemd-networkd drop-in under /etc/systemd/network and a policy environment file under /etc/link-rate.d. Detached interfaces get no account and nothing on disk, though their ledger rows still belong in the chain. An interface carries months of daily egress volume rows, and its shaping numbers fall out of those rows once the ordered shaping adjustments and the smoothing pass have run over them. The whole run ends up summarized in a sealed manifest whose seal chains over every ledger row in registry order. The record layout, the arithmetic, the file contents, the manifest schema and the seal are all spelled out in /app/docs/LINKS.md, so read that before touching anything.

The ledger records are packed in Redis on 127.0.0.1 port 6379. A small Slim API on 127.0.0.1 port 8080 serves the interface list, the per interface metadata and the shaping adjustments. Both come up with /app/scripts/start-services.sh.

Write /app/bin/provision-link-rates, an executable that provisions every interface the API lists. It writes the manifest to /app/out/link-manifest.json and puts the same 16 lowercase hex digit seal in /app/out/seal.hex with a trailing newline. Running it a second time cannot change any account or file, and it has to produce identical outputs. The container has no network access.
