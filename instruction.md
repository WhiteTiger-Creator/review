Please settle a Lantern Grid board-game table from the tournament ledger at `/app/task_file/public_ledger.json`. The match has conflicting turns, reserve pieces, house caps, relay paths, and round tracks; the table needs the final scorecard.

Put the Lantern Grid table scorer at `/app/bin/lantern-referee`. The desk calls `/app/bin/lantern-referee --input /app/task_file/public_ledger.json --output /app/out/scorecard.json`, and it will also replay unseen Lantern Grid ledgers with the same match-card fields. The `--output` flag is optional; when it is omitted, write the scorecard to `/app/out/scorecard.json`. Create the output parent directory if needed and write only the scorecard JSON.

Use `/app/task_file/rulebook/lantern_grid_rulebook.txt` as the table rule sheet. It defines legal pieces, board caps, final scoring constraints, leveling, miss reasons, and the exact scorecard shape. Scorecard lists must always be arrays; for example, if no turns are scored, emit `"scored": []` rather than null. Follow the Lantern Grid rules generally rather than matching only the public match.

Two late-board rules are easy to miss, so keep these rule-sheet details in the implementation too. For `relay_paths`, filter the listed `members` down to scored turns but keep the order from the `members` array; do not reorder by ledger turn order or round. Each adjacent scored member pair must be connected by labels on the selected pieces: one side needs `<edge_label_prefix>:<left_member>:<right_member>` or the other side needs `<edge_label_prefix>:<right_member>:<left_member>`. The scored member rounds must fit `max_round_span` unless every selected piece for those scored members has `relay-wide:<name>`. If an adjacent pair has the same subject, both selected pieces for that pair also need `relay-subject:<name>:<subject>`. `min_score` and `min_distinct_pieces` are final checks over that relay path's selected scored members.

For `claim_markets`, reserve candidates are ordinary top-level `pieces`, not a separate reserve object and not turn records. Process the market `members` in order after dropping unscored members. For each scored member, claim the first piece by piece id that is playable for that same turn, has the market `claim_label`, has the same subject as the turn, is not the selected piece for that turn, and was not already claimed by that same market. Claimed reserve pieces are then checked against `min_claims`, `min_claim_houses`, and `max_claim_burden`; final scoring-row limits do not apply to those reserve pieces, and unusable reserve candidates do not add miss reasons.
