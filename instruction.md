Audit the clock selection of a time synchronisation fleet. Every host polls a handful of upstream time servers, and each poll yields a correctness interval, a range the host believes its true clock error lies within, with the measured offset it is built around. The fleet has been captured as a graph in an embedded Kuzu database at /app/graph/timesync.kuzu, whose tables and properties are described in /app/docs/schema.md.

Only measurements from reachable, synchronised servers are used. Among those, the host finds the range where enough intervals agree, tolerating as few disagreeing servers as it can: it takes the tightest agreement first and widens its tolerance one server at a time only when it must. A server is trusted when its measured offset lands inside that agreed range and distrusted when it does not, so a wide interval that straddles the range while its offset sits outside is an outlier, not an ally. Each host then steers by one trusted server and inherits a stratum from it; a host that finds no agreement is left unsynchronised.

The precise definitions of eligibility, coverage, the tolerated intersection, the truechimer and falseticker verdicts and the derived stratum are stated in full in /app/docs/selection_rules.md, and every one affects the result.

Provide the certification as a single Cypher query saved to /app/answer.cypher, returning one row per host under exactly five columns named client, stratum, system_peer, truechimer_count and falseticker_count. The result shape and query tips are in /app/docs/output_contract.md and /app/docs/query_tips.md; worked schema-name examples are in /app/docs/property_reference.md.
