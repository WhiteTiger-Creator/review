You are auditing the framekit frame decoder for an out-of-bounds read on its unsafe fast decode path. The evidence sits under /app/environment. docs/frame-format.md is the authoritative dispatch and arithmetic contract, and reference/src holds the disclosed decoder revisions the contract describes: the fast path, the original decoder, and a guarded revision that closes the gap. There is no network access.

The file cases.jsonl is the evidence to rule on. Each line is one case, a JSON object with an id, a config_text giving that case's build configuration, and a frame_hex giving the frame's raw bytes in hex. For every case decide, per the contract, whether the fast path would read past the end of the frame's own buffer, and if it would, the exact byte range that read would cover. Two independent gates decide whether that path runs at all, a compile-time feature and a per-frame runtime flag carried in the configuration and the frame, and the guarded revision closes the gap regardless. The hard part is the length math: a declared length smaller than the header underflows one subtraction but can wrap the final range back inside the buffer, which is safe, so resolving only the first wraparound is wrong.

Write your findings to /app/verdicts.txt, one line per case as the case id, a space, then its verdict. The verdicts are MALFORMED, REJECT_MAGIC, REJECT_OUTER_LEN_BOUND, SAFE_NO_UNSAFE_READ, REACHABLE_SAFE, and REACHABLE_EXPLOITABLE:start-end with the range as plain decimals. Worked cases with their answers sit in examples.jsonl.
