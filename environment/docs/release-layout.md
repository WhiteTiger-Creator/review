# Release layout and trust contract

Each release has payload directories `bin`, `lib`, and `requests`. `release.manifest` is the sorted SHA-256 inventory of every regular payload file, with normalized relative paths and no duplicates. `release.id` is the lowercase SHA-256 of the exact manifest bytes. The release slot is `<release-name>-<release.id>`; the same healthy payload therefore has one slot and does not manufacture rollback history.

Trusted metadata consists of `release.provenance`, `release.attestation`, and `release.signature`. Provenance starts with `abi LEDGER_2.1`; each remaining line is `elf <relative-path> <GNU-build-id>` for the gateway and every real policy, rules, and audit ELF in the baseline and `x86-64-v3` stacks. Those ELF paths are sorted, unique, and relative. Attestation has exactly three newline-terminated fields named `release_id`, `abi`, and `provenance_sha256`, binding the manifest identity, `LEDGER_2.1`, and the SHA-256 of the exact provenance bytes. The detached Ed25519 signature is checked with `/app/packaging/release-signing.pub`; the private signing key is never copied into a runtime root. Metadata files are not entries in the payload manifest.

The common ABI lives directly under `lib`; hardware-specific replacements use `lib/glibc-hwcaps/x86-64-v3`. Both generations share SONAMEs, but rules and audit exports use generation-specific symbol versions. Policy exports use `LEDGER_POLICY_2.1`, and the gateway requests that versioned interface rather than accepting an unversioned lookalike. A policy depends on the matching rules and audit libraries with an origin-relative runpath.

The request catalog is `settlement`, `refund`, `reconcile`, and `drain`. Their baseline decisions are `accept`, `review`, `hold`, and `quiesce`; optimized decisions add `vector-`. Drain carries a bounded 3500 ms pause so an in-flight native process can cross an attempted refresh. Output still reports request, plugin, rules, audit, generation, ABI, and decision.

All in-release links are relative and remain inside their release. Payload and metadata are not writable by group or other users. The gateway is executable, libraries carry GNU build IDs, and no runtime file is supplied by a host library path.
