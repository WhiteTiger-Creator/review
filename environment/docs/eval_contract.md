# Offline ward-census occupancy nowcast machine-learning evaluation contract

This document elaborates the offline machine-learning evaluation for frozen-checkpoint occupancy nowcasting: feature embeddings, held-out adversarial generalization on clock-discontinuity arms, occupancy-conservation digests, and scored-stage tip agreement. The inference stack under `/app/environment` must satisfy every rule below when invoked through the documented evaluation entrypoint.

## Artifact

Path: `/app/output/invariant_proof_log.json`

Must be regenerated by the published Go evaluation entrypoint. Static hand-written files that skip that pipeline are invalid even when schema-shaped. Consecutive runs with the same inputs must be byte-identical (truncate then write; no append residue).

## JSON schema (`occ-proof-v1`)

```json
{
  "schema": "occ-proof-v1",
  "slice": 3,
  "seed": <uint32 seed of the primary held-out arm>,
  "metrics": [
    {
      "arm": "<arm name>",
      "score_tag": "<12 lowercase hex chars; primary write-lane tag>",
      "lat_hex": "<16 lowercase hex chars>",
      "jmp_hex": "<16 lowercase hex chars>",
      "a_cnt": <non-negative int>,
      "b_cnt": <non-negative int>,
      "z_lim": <non-negative int>,
      "unit_key": "<16 lowercase hex chars>",
      "cite": "<12 lowercase hex chars; equals score_tag>"
    }
  ]
}
```

No boolean verdict fields. Field values are observations derived from the rules below.

Resource preservation predicate for every metrics row:

`a_cnt + b_cnt == z_lim`

(domain reading: occupied + vacant = capacity on each cited ward-horizon unit)

## Feature pack (`fixtures/feat_blob.bin`)

Little-endian layout:

- magic `FEAT`
- `u16` row count, `u16` feature count, `u32` stamp
- repeated records: `u16` identity id, `u8` role (`0` write-capable, `1` observation-only), `u8` pad, then `feature_count` float64 feats, then `i16` a_base, `i16` b_base, `u16` lim

## Frozen weights (`weights/w_blob.bin`)

- magic `WB01`
- `u16` dim, then `dim` float64 weights, then float64 bias

## Pinned annex lock (`data/pin_s.lock`)

- magic `PIN1`
- `u16` slice id, `u32` seed
- `u16` id count, then that many `u16` identity ids in packing order

Pinned slice id is `3`. Do not re-slice. Evaluation partitions follow this lock.

## Partition cache (`data/part_cache.bin`)

- magic `PC01`
- `u32` stamp, `u16` slice, `u16` id count, then that many `u16` identity ids

Accept the cache only when `stamp` equals the feature-pack stamp and `slice` equals `3`. A sentinel or mismatched stamp (including `0xDEADBEEF`) is invalid: rematerialize packing from `pin_s.lock` before scoring, then rewrite the cache. Do not trust blob file order or a stale cache order for `score_tag` / `cite`.

## Run epoch (`data/run_epoch.bin`)

- magic `RN01`
- `u32` stamp, `u16` slice

Accept only when `stamp` equals the feature-pack stamp and `slice` equals `3`. A sentinel or mismatched epoch is invalid: rematerialize before scoring and rewrite RN01. Warm-shadow residue must not force training-annex packing over pin order.

## Feature-identity packing and score tags

1. Load every record from the feature pack, indexed by identity id.
2. Emit rows in the identity order listed in `pin_s.lock` (not absolute blob file order).
3. For each identity id, `score = w · feats + bias`.
4. Opaque score tag: first 12 hex chars of sha256 of the UTF-8 string
   `id=<id>|sc=<score with 6 decimal places>|seed=<arm seed>|arm=<arm index>`
   where arm index is the 0-based index of the arm entry in `data/xtra_clk.toml`.
5. Primary `score_tag` / `cite` for a metrics row is the tag of the first write-capable identity in pin order (insertion order).

Two distinct tag-order rules (do not conflate):
- `score_tag` / `cite`: pin packing order (first write-capable along `pin_s.lock`).
- `lat_hex` write-tag list: lexicographically sorted write-capable tags before hashing.

## Type-and-effect role gates

- Role `0` (write-capable): a_base / b_base / lim contribute to lattice counts.
- Role `1` (observation-only): must not write occupancy counters; ignored for `a_cnt`, `b_cnt`, and `z_lim` aggregation.
- Lattice pre-jump counts: sum a_base, sum b_base, sum lim over write-capable rows only.
- `lat_hex` is the first 16 hex chars of sha256 of
  `lat|<sorted write tags joined by comma>|<a>|<b>|<lim>`
- `unit_key` is the first 16 hex chars of sha256 of
  `unit|<lat_hex>|<arm name>`
- Fold must carry pin-order cite authority and the matching cite-authority seal into bind.
- Cite-authority seal is the first 16 hex chars of sha256 over `seal|<cite>`.

## Clock discontinuity rebinding

Arms in `/app/environment/data/xtra_clk.toml` publish `name`, `kind`, `seed`, `jump`, and `rotate`.

For a held-out arm with pre-jump lattice counts `(a, b, lim)` and jump `J`:

- `a_cnt = (a + J) % lim` when `lim > 0`, else `a`
- `b_cnt = lim - a_cnt`
- `z_lim = lim`

`jmp_hex` is the first 16 hex chars of sha256 of

`jmp|<arm>|<seed>|<a_cnt>|<b_cnt>|<z_lim>|<lat_hex>|<rotate>`

Held-out arms (`kind = "hold"`) must appear in `metrics` with zero derived preservation violations. Training arms may be used for diagnostics but do not satisfy held-out survival.

Primary document seed is the seed of the first held-out arm in `xtra_clk.toml` order (`hold_rot_a` / `4242`). Metrics rows are sorted by ascending arm name.

## Dependence closure

Edits to lag features after a discontinuity must recompute effect obligations (lattice aggregation and jump digest) before scoring into the proof log.

Cross-stage tip agreement is required for a single run and must survive durable tip-journal recovery: pack identity and scored row identity must be visible before lattice aggregation, folded lattice identity (including pin-order cite authority, cite-authority seal, and the active pack fingerprint) must be visible before discontinuity rebinding, and rebound digests must be visible before proof-log flush. Warm lattice-memo reuse is valid only when pack and row fingerprints match and cite authority remains pin-order. Scored rows must re-dot against frozen weights under pin packing before fold acceptance. Fresh evaluation must clear warm-shadow and scored-row residue so training-window short-circuits do not replace held-out fold. Post-score / post-fold / post-bind hooks on the evaluation entrypoint must preserve pin packing order, pin-order cite seals, and bound digests through flush. Stages that skip durable tip persistence, omit pack fingerprints, leave warm-shadow markers, or emit while tips disagree are not contract-correct. Consecutive runs must clear tip and memo residue so replay stays byte-identical. A successful held-out emit must leave durable tip-journal recovery state under `data/.tip_snap` where `gen` counts committed tip generations, and must rematerialize a run epoch whose stamp equals the feature-pack stamp.

## Rerun stability

Running the CLI twice against the same root and output path must leave the proof log byte-identical.

## Offline

No network egress. All inputs are local under `/app/environment`.
