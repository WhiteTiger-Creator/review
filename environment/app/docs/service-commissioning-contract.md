# Service commissioning publication contract

The operations snapshot is the exact stdout of `/app/bin/catalog-query --batch-file /app/share/service-catalog.batch`. The maintenance snapshot is the exact stdout of the same interface with `HARBOR_CATALOG_DB=/opt/harbor/maintenance-window.db` and `/app/share/maintenance-window.batch`. The raw SQLite files are not operator interfaces.

`/app/var/commissioning-manifest.json` is compact UTF-8 JSON plus one newline. Top-level keys are ordered: `run_id`, `site_key`, `handbook_revision`, `catalog_generation`, `schedule_generation`, `configuration`, `routes`, `assertions`, `window_plan`, `inputs`, `publication`. Configuration values are strings. Route objects use `method`, `external_path`, `upstream`, `auth_mode`, `timeout_ms`, `source_route_id`, `cohort_code`, `decision_code`. Assertion objects use `name`, `passed`, `observed`, `rule_ref`, with integer `passed=1`.

The nine input records are sorted by `kind` and `path`: `window-meta`; `catalog-batch-result`; `maintenance-window-batch-result`; `socket-inventory`; `request-manifest`; three `request:<role>` records; and `socket-open-trace`. Catalog records describe exact stdout bytes; other records describe the named files.

Publication entries are ordered: `/app/etc/harbor-relay/relay.conf`, `/app/etc/harbor-relay/limits.conf`, `/app/etc/harbor-relay/routes.map`, `/app/var/window-plan.json`, `/etc/systemd/system/harbor-relay.service`, `/app/var/commissioning-ledger.db`, `/app/var/commissioning-manifest.json`. The first five carry real SHA-256 and byte counts. The ledger and manifest use 64 zeroes and byte count 0 to avoid recursive identity. Modes are `0640`, `0644`, or `0600` as appropriate. `/app/var/harbor-commissioning.lock` is required, empty, mode `0600`, and excluded from publication.

A digest-line set writes every lowercase digest followed by `\n`, including the last. `request_set_sha256` uses the request manifest then role files in manifest order. `record_set_sha256` uses `/app/records/window.meta`, `/app/records/socket-allocation-events.txt`, `/app/records/socket-occupancy-snapshot.txt`. The 24-character `run_id` is the first lowercase hex portion of SHA-256 over the pipe-joined sequence: site key, handbook revision, catalog generation, schedule generation, request-set digest, record-set digest, operations snapshot digest, maintenance snapshot digest, readiness digest, relay.conf digest, limits.conf digest, routes.map digest, service-unit digest. No newline is appended.
