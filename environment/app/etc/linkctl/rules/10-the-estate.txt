THE LINK RULES
THE HOST AND THE FORM OF EVERYTHING READ FROM IT (N001 through N034)

These clauses say where the host's tables and its recorded run stand, and how every file
beneath the link root is read. They settle nothing on their own: they only fix what each file
says. The clauses that decide a state begin at N035.

--- The link root and the form of its files (N001 through N004) ---

N001  The host's tables and its recorded run stand under the link root. Every file named in
these rules is read from beneath that root. Nothing beneath the link root is ever written,
moved or removed while the host is settled. These rules stand outside that root, at
/app/etc/linkctl/rules, and nothing an operator or the run could write can reach them.

N002  Every file beneath the link root is plain ASCII text holding one record to a line, each
line ending with one line feed.

N003  A line whose first character is a number sign carries no record, and a line holding only
blank space carries no record. Blank space at the start and at the end of a line, and blank
space on either side of a field separator, is not part of any field.

N004  A record carries its fields separated by single colons, in the order the clause for that
file gives. A single hyphen written where a value is expected means no value at all on that
field. Interface names, bond names, VLAN names, slot names and address texts are compared as
byte sequences in ascending order, and where one is a prefix of another the shorter one stands
first. Every clause of these rules that speaks of ascending order means this comparison and no
other. Every count in these rules is a whole number and every piece of arithmetic is whole
number arithmetic; no fraction, ratio or percentage appears anywhere in this host.

--- host.conf (N005 through N006) ---

N005  host.conf holds one setting to a line, written as the setting's name, an equals sign and
its value.

N006  host is the name of the host and is printed on the head line of the report.

--- The interface table (N007 through N012) ---

N007  links/interfaces.table holds one physical interface to a line, carrying three fields: the
interface name, the slot it sits in on the machine, and its link standing when the run opens,
written up or down.

N008  Interface names are distinct. THE ORDER OF THE LINES OF THIS FILE IS THE INTERFACE TABLE
ORDER, top line first, and it is the order the interface block of the report is printed in, by
N147.

N009  The slot is carried straight through to the report and decides nothing at all. Two
interfaces never share a slot.

N010  An interface written up in this file has a link that stands when the run opens, and it
has therefore stood at some moment. An interface written down has a link that does not stand
when the run opens, and it has NOT stood at any moment unless a step in the run raises it.

N011  A physical interface is a card in a slot on this machine. It stands in the estate before
the run opens and it is still declared when the run closes. NO STEP OF THE RUN adds a physical
interface to this table or takes one away from it.

N012  EVERY PHYSICAL INTERFACE THIS TABLE NAMES takes exactly one state out of the closed set
of five at N148 and prints exactly one line in the interface block, whatever the run did to it
and whether or not any bond, VLAN or address ever names it.

--- The bond table (N013 through N018) ---

N013  links/bonds.table holds one bond to a line, carrying three fields: the bond name, its
member floor, and whether it stood raised when the run opens, written yes or no.

N014  Bond names are distinct, and no bond carries the name of a physical interface or of a
VLAN. THE ORDER OF THE LINES OF THIS FILE IS THE BOND TABLE ORDER, top line first. That order
is weighed in three places: it is the order bonds raised at the open are raised in by N034, it
is the order the enrolment rule of N044 reads, and it is the order the bond block of the report
is printed in by N151. A bond standing LOWER in the bond table is one written FURTHER DOWN the
file, that is, on a later line.

N015  A bond's MEMBER FLOOR is the number of counted members it is meant to keep. It is a whole
number, zero or more. It is read from this file and never changes during the run.

N016  A BOND WHOSE MEMBER FLOOR IS ZERO can never have its counted members fall under the
floor, whatever happens to its members, so it is never in reduced standing. N089 says so again.

N017  A bond written yes in the third field stands raised when the run opens. A bond written no
does not, and it has NOT been raised at any moment unless a step in the run raises it.

N018  A bond is standing configuration on this host, named by this table. It prints a line in
the bond block even where it was never raised, and NO STEP OF THE RUN adds a bond to this table
or takes one away from it.

--- The member table (N019 through N022) ---

N019  links/members.table holds one declared membership to a line, carrying three fields: the
bond, the physical interface it declares as a member, and that member's declared place.

N020  A declared place is a whole number, one or more, and the places a single bond declares
are distinct. THE DECLARED LADDER ORDER of a bond is its declared members ordered ASCENDING BY
DECLARED PLACE, the lowest number first. Every member named here is a physical interface the
interface table names. A bond this file names on no line at all declares no members.

N021  THE SAME PHYSICAL INTERFACE MAY BE DECLARED BY MORE THAN ONE BOND. Which bond actually
enrols it is settled by the enrolment rule at N044 and by nothing else. A bond may not declare
the same member twice.

N022  The declared ladder order is the order a raise rebuilds a bond's ladder in, by N081, and
the declared count is the number of members the member table declares for that bond, by N064.

--- The VLAN table (N023 through N026) ---

N023  links/vlans.table holds one VLAN interface to a line, carrying four fields: the VLAN
name, its parent, its tag, and whether it stood raised when the run opens, written yes or no.

N024  VLAN names are distinct, and no VLAN carries the name of a physical interface or of a
bond. A VLAN names exactly one parent and that parent never changes. A PARENT IS A PHYSICAL
INTERFACE OR A BOND AND IS NEVER ANOTHER VLAN, so no VLAN is ever stacked on a VLAN.

N025  A tag is a whole number. It is carried straight through to the report and decides nothing
at all.

N026  THE ORDER OF THE LINES OF THIS FILE IS THE VLAN TABLE ORDER, top line first, and it is
the order the VLAN block of the report is printed in by N153. A VLAN interface is standing
configuration on this host: it prints a line even where it was never raised, and NO STEP OF THE
RUN adds a VLAN to this table or takes one away from it.

--- The address table (N027 through N030) ---

N027  links/addresses.table holds one address record to a line, carrying four fields: the
record's rank, the address text, the interface the record is declared on, and whether the
record stood claimed when the run opens, written yes or no.

N028  Ranks are whole numbers, distinct, ascending from one down the file. THE ADDRESS TABLE
ORDER is ascending by rank, so the record standing HIGHEST in the address table is the one
declared FIRST, with the lowest rank, and the record standing LOWEST is the one declared LAST,
with the highest rank. The pair of an address text and an interface appears on at most one line
of this file, so a claim or a release step names exactly one record.

N029  MORE THAN ONE RECORD MAY NAME THE SAME ADDRESS, and the records naming one address may
stand on any mixture of physical interfaces, bonds and VLANs. The interface a record names is a
physical interface the interface table names, a bond the bond table names, or a VLAN the VLAN
table names.

N030  EVERY ADDRESS RECORD THIS TABLE DECLARES takes exactly one state out of the closed set of
five at N138 and prints exactly one line in the address block. A record is a line of standing
configuration: it does not arrive during the run and it does not depart, and NO STEP OF THE RUN
adds a record to this table or takes one away from it.

--- The recorded run and its eight step kinds (N031 through N034) ---

N031  run/link.log holds one step to a line, carrying four fields: the step number, the step
kind, the first name the step reaches, and the second name it reaches or a single hyphen where
the kind reaches only one name. THE STEPS ARE WEIGHED IN ASCENDING STEP NUMBER, first line
first, and each is applied in full before the next is read.

N032  There are EIGHT STEP KINDS AND NO OTHERS:
      link-down  the interface named in the first field, second field a hyphen
      link-up    the interface named in the first field, second field a hyphen
      detach     the bond in the first field, the member in the second
      attach     the bond in the first field, the member in the second
      raise      the bond or VLAN named in the first field, second field a hyphen
      lower      the bond or VLAN named in the first field, second field a hyphen
      claim      the address text in the first field, the record's interface in the second
      release    the address text in the first field, the record's interface in the second
A raise step and a lower step name a bond where the bond table names it and a VLAN where the
VLAN table names it; the two name spaces are kept apart by N014 and N024.

N033  EVERY STEP NAMES SOMETHING THE TABLES ALREADY DECLARE. A link step names an interface the
interface table names; an attach or detach step names a bond the bond table names and an
interface the interface table names; a raise or lower step names a bond or a VLAN the tables
name; a claim or release step names a record the address table already declares. IT FOLLOWS
THAT NO STEP CAN ADD A LINE TO THE REPORT OR TAKE ONE AWAY, and N158 says what that means for
the shape of the report.

N034  THE OPEN. Before step one is weighed, the estate stands as its tables declare it: every
link stands or does not by N010, every bond written raised at the open is raised, IN BOND TABLE
ORDER, exactly as N081 describes a raise, every VLAN written raised at the open stands, and
every record written claimed at the open is claimed. The order of work at N075 is then done
once, before step one. A RUN THAT CARRIES NO STEPS AT ALL is an ordinary run of this host: the
estate is settled exactly as the open left it, and every block and every tally is printed in
full.
