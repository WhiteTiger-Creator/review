Edit only /app/work/playbook/strategy.json. The sealed relayplayer evaluates rules in listed order and applies the first matching rule. When no rule matches, it applies fallback. Order is load bearing. A single global fallback that always captures or always stays quiet fails families that need opposing contingencies.

Rule objects use id, when, and then. when fields are optional filters. ply_at_most and ply_at_least bound the ply index. in_check, has_ready_drops, has_legal_captures, has_promotion, and has_stale_near_king are booleans. queue_room_at_least compares capacity minus length. queue_full is true when length is at least capacity. visible_pieces_min and visible_pieces_max count visible pieces in the observation. board_is matches alpha or beta. has_flags requires every listed durable flag already set this match. lacks_flags requires none of the listed flags set yet.

then.action is one of escape, capture, quiet, drop_near_king, drop_any, request, promote_queen, promote_knight, or hold. capture_weight, king_hunt_weight, king_move_penalty, and check_escape_bonus are integer scores. avoid_stale_king_walk true refuses king walks onto stale sightings of age at most stale_age_max. suppress_capture_max ignores captures whose material value is at most that number. prefer_quiet true skips captures when choosing quiet or unrelated actions. request_piece names the default request kind. set_flags and clear_flags update durable match memory after the contingency fires. Flags persist across plies inside one campaign and reset between campaigns.

Context reversals. Checked seats need an early escape rule before quiet fallback, or check replies fail and hold_in_check faults appear. Ready drops under check or near aged sightings need drop_near_king, or defensive-drop floors fail. Busy boards with queue room and empty ready lists need a ply-bounded request before hunting, or long linked matches miss the required request in the ply log. When the queue is full, a suppress or quiet rule must outrank greedy capture, or queue-pressure and capacity-one campaigns clog the relay and miss acceptance. Overflow captures subtract captured piece value from pending relay score. Promotion with queue room wants promote_queen; promotion with a full queue wants promote_knight so overflow captures do not waste the only slot. Always requesting fails short endgames; always capturing fails full-queue families; always quiet fails material and promotion floors.

At most 24 rules. fallback is required. Examples below teach grammar only and are strategically weak.

Example 1. Empty rules with prefer_quiet true in fallback validates and finishes matches yet fails material, promotion, request, and drop floors.

Example 2. A lone capture rule with no check, request, drop, or queue_full contingency validates yet fails defensive-drop, busy-request, and queue-pressure campaigns.
