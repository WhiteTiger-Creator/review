# Confidential inference partition contract

The command receives an input bundle directory followed by an output JSON path. Exactly two positional arguments are required; any other argument count must exit nonzero. For a compatible bundle, the command must treat all input files as read-only, create any missing parent directories for the output, overwrite an existing output, produce the object described below, and exit zero. This includes a compatible bundle with no feasible placement: `unsatisfied` is a successful planning result, not a process error. Behavior for malformed bundles outside the compatibility requirements below is not specified.

All input and output numeric fields are JSON integers, and all arithmetic uses signed 64-bit integers. Compatible bundles guarantee that every derived latency, exposure, memory, key-use, count, and objective value fits in that range. The value of `ceil(tensor_bytes / 1024)` must remain exact when `tensor_bytes` is the largest signed 64-bit integer; an overflowing intermediate result is invalid. Input arrays define ordering only where this contract explicitly refers to row order; eligibility-list order never expresses preference.

## Bundle files

`graph.json` contains `workload_id`, `nodes`, `edges`, and `enclave_groups`. `workload_id` is a nonempty string. Nodes are already in topological order and have nonempty string `id`, nonempty string `op`, string `classification`, and positive `output_bytes`; IDs are unique and classification is `public`, `restricted`, or `secret`. Edges have unique nonempty string `id`, string `from`, string `to`, string `sensitivity`, and positive `tensor_bytes`; both endpoints name nodes, `from` precedes `to`, and sensitivity uses the same three labels. An enclave group is an array of at least two node-ID strings. Groups do not overlap.

`providers.json` contains `providers`, `transfers`, and `conversions`. Each provider has unique nonempty string `id`, positive `memory_bytes`, nonnegative `startup_us`, Boolean `remote`, nonnegative `trust_level`, nonnegative `attestation_epoch`, nonnegative `key_slots`, and `capabilities`. A capability has a nonempty string `op` and a nonempty `modes` array; each mode has a nonempty string `name` unique within that capability plus nonnegative `latency_us`, `workspace_bytes`, and `exposure_ppm`. Provider IDs and mode names never contain `/`, making the canonical `provider_id/mode` sequence encoding unambiguous. There is at most one capability for an operation on a provider. Transfers have string `from_provider`, string `to_provider`, Boolean `encrypted`, and nonnegative `fixed_us`, `per_kib_us`, and `exposure_ppm`; they are unique by ordered provider pair. Conversions have string `from_mode`, string `to_mode`, and nonnegative `latency_us` and `exposure_ppm`; they are unique by ordered mode pair. Every transfer or conversion required by a candidate complete placement is present.

`policy.json` contains `allowed_provider_ids`, `minimum_trust`, `minimum_attestation_epoch`, `max_path_exposure_ppm`, `max_remote_nodes`, `max_transfers`, `max_conversions`, and `placement_rules`. `minimum_trust` has exactly the integer fields `public`, `restricted`, and `secret`; all limits and thresholds are nonnegative. `allowed_provider_ids` contains unique provider-ID strings. A placement rule has a string `node_id` naming a node, a nonempty `allowed_provider_ids` array, and a nonempty `allowed_modes` array; there is at most one rule per node. Policy and rule arrays are eligibility sets, not preference order, and provider, capability, and mode array order does not break objective ties.

Compatible verifier bundles contain 1–18 nodes, 1–4 providers, no more than five eligible provider/mode choices per node, and values whose specified sums fit signed 64-bit integers.

## Security and resource feasibility

A placement assigns every node one provider and one mode from that provider's capability for the node's `op`. The provider must occur in `allowed_provider_ids`, have `attestation_epoch` at least `minimum_attestation_epoch`, and have `trust_level` at least the `minimum_trust` threshold for the node's classification. A placement rule, when present, additionally requires both its provider and mode. Every node in an enclave group must use exactly the same provider and mode.

Provider memory is the sum, over nodes placed there, of that node's `output_bytes` plus the chosen mode's `workspace_bytes`; it must not exceed `memory_bytes`. For each edge whose endpoint providers differ, use the ordered transfer row. If the edge sensitivity is `restricted` or `secret`, that transfer must have `encrypted: true`. Each encrypted transfer edge consumes one key slot on both endpoint providers, so each provider's total used key slots must not exceed its `key_slots`. The number of nodes on remote providers may not exceed `max_remote_nodes`.

For each edge, `transfer` is true exactly when endpoint providers differ, `conversion` is true exactly when endpoint modes differ, and `encrypted` is true exactly when a transfer occurs through an encrypted transfer row. A transfer contributes `fixed_us + ceil(tensor_bytes / 1024) * per_kib_us` latency and its `exposure_ppm`; a conversion contributes its `latency_us` and `exposure_ppm`. When both occur, both contributions are added. A complete placement may contain at most `max_transfers` transfer edges and at most `max_conversions` conversion edges.

Path exposure is computed in node order. A source node's path exposure is its chosen mode's `exposure_ppm`. For any other node, take the maximum over incoming edges of the predecessor's path exposure plus that edge's transfer and conversion exposure, then add the node mode's `exposure_ppm`. The placement's `path_exposure_ppm` is the maximum node path exposure, including disconnected sources, and must not exceed `max_path_exposure_ppm`.

## Canonical optimum

For a feasible placement, node latency is the sum of chosen mode `latency_us`; boundary latency is the sum of all edge transfer and conversion latency; startup latency is the sum of `startup_us` once for each used provider. `total_latency_us` is their sum. `max_provider_memory_bytes` is the largest provider-memory sum, including zero for unused providers, and `max_provider_key_slots_used` is the largest used-key count, also including unused providers.

Choose the feasible placement with the lowest tuple, in this exact order: `total_latency_us`, `path_exposure_ppm`, `max_provider_memory_bytes`, `max_provider_key_slots_used`, transfer count, conversion count, then the complete placement sequence. The sequence has one string per node in node order, formatted `provider_id/mode`; compare sequences lexicographically by Unicode code point. Tie-breaking compares the complete sequence, never a locally tied node choice.

## Output

Write one JSON object with exactly `workload_id`, `status`, `placements`, `boundaries`, `provider_resources`, and `metrics`. The string `workload_id` must equal the input graph's value. The only status strings are `ok` and `unsatisfied`: use `ok` with the canonical optimum whenever at least one feasible placement exists. Otherwise use `unsatisfied`; `placements`, `boundaries`, and `provider_resources` are empty arrays, and `metrics` is null.

For `status: "ok"`, `placements` has one entry per node in node order with exactly string `node_id`, string `provider_id`, and string `mode`. `boundaries` has one entry per edge in edge order with exactly string `edge_id`, Boolean `transfer`, Boolean `conversion`, Boolean `encrypted`, integer `latency_us`, and integer `exposure_ppm`. An edge with neither transition has false flags and zero latency and exposure; when both transitions occur their contributions are added. `provider_resources` has one entry per provider in provider order, including unused providers, with exactly string `provider_id`, integer `used_bytes`, and integer `used_key_slots`.

For an `ok` plan, `metrics` has exactly `node_latency_us`, `boundary_latency_us`, `startup_latency_us`, `total_latency_us`, `path_exposure_ppm`, `max_provider_memory_bytes`, `max_provider_key_slots_used`, `transfer_count`, `conversion_count`, `encrypted_transfer_count`, and `remote_node_count`. Every numeric output is a JSON integer. Empty arrays remain arrays, and no additional fields are allowed.
